### 2. 오늘 가장 의미있었던 기술적 판단

- 내가 내린 판단:
  - 알림을 데이터 소스가 아니라 "변경 신호"로만 쓰기로 했다 (PR #379). `EVAL_REQUESTED`가 도착하면 알림 페이로드로 목록 행을 만들어 끼워 넣지 않고, 해당 쿼리 키의 캐시를 무효화한 뒤 기존 조회 API로 서버에서 다시 읽는다.
  - 여기에 절충을 하나 더 얹었다 — 목록 화면이 열려 있으면 즉시 재조회하고, 다른 화면에 있으면 오래된 것으로만 표시하고 다음 진입 때 읽는다.

- 그렇게 판단한 이유:
  - 알림 문구는 사람에게 보여 주려고 만든 문자열이지 목록 행의 스키마가 아니다. 목록에는 알림에 없는 값(배정 상태, 신청 시각 기준 정렬 위치)이 있어서, 알림으로 행을 만들면 서버가 주는 행과 모양이 다른 두 종류의 행이 한 목록에 섞인다.
  - 배정 대기 목록은 여러 평가사가 경쟁적으로 가져가는 목록이다. 내가 알림을 받은 순간 이미 남이 배정해 간 신청일 수 있다. 낙관적으로 끼워 넣으면 "화면에는 있는데 누르면 없는" 상태가 정상 동작으로 자주 나온다.
  - 재조회 비용은 이 목록 규모에서 무시할 만하고, 서버가 항상 진실이라는 경계가 하나로 유지된다.

- 고려했지만 선택하지 않은 대안:
  - 알림 페이로드로 목록에 낙관적 삽입 — 네트워크 왕복이 없어 가장 빠르다. 위의 경쟁 상황과 스키마 불일치 때문에 기각.
  - 목록 전용 SSE 채널 신설 — 정확하지만 채널을 하나 더 만들어야 하고, 이미 회원별 알림 채널이 같은 사건을 이미 밀고 있다. 같은 사건에 통로 두 개는 오버엔지니어링이라 기각.
  - 목록 화면에서 짧은 주기 폴링 — 구현은 제일 싸지만, 알림 통로를 이미 깔아 놓고 폴링을 얹는 건 앞선 결정을 부정하는 것이라 기각.
  - 모든 알림에 대해 무조건 무효화 — 코드가 제일 짧다. 관계없는 알림 한 건에 목록 재조회가 붙어 기각하고, 알림 종류로 분기했다.

- 이 판단이 코드 품질/테스트/유지보수에 미친 영향:
  - 배정 대기 목록을 쓰는 두 화면(평가사 홈, 배정 대기 목록)과 알림 수신부가 같은 쿼리 키 하나를 공유하게 정리됐다. 갱신 지점이 한 곳이라 다음에 화면이 하나 더 늘어도 붙일 자리가 명확하다.
  - 테스트가 "화면에 뭐가 보이나"가 아니라 "활성 쿼리는 즉시 재조회 / 비활성은 무효화만 / 다른 종류 알림은 무반응" 이라는 계약 단위로 잡혔다. 프런트 테스트 155개 통과.
  - 다만 이 판단이 #380(분할 조회)을 강제로 불러냈다 — 목록이 커지면 무효화 후 전체 재조회 비용이 그대로 커진다. 오늘 이슈로 남겼다.

### 3. 가장 막혔던 문제와 해결 과정

- 문제 상황 또는 증상:
  - 알림함이나 경매 미리보기를 열고 닫을 때마다 화면 전체가 좌우로 한 번 흔들렸다(#370). 특정 환경에서만 재현돼서 처음엔 내 착각인가 싶었다.

- 처음 추측한 원인:
  - 오버레이가 열릴 때 레이아웃이 리플로우되는 CSS 문제라고 봤다. 헤더의 `position`이나 컨테이너 `max-width` 쪽을 의심했다.

- 원인을 확인하기 위해 시도한 방법:
  - 오버레이 열림 전후로 `document.documentElement`의 computed style을 직접 비교했다. 흔들림 폭이 정확히 스크롤바 폭과 같다는 걸 보고 방향을 바꿨다.
  - 오버레이가 열린 순간 `<body>`에 붙는 인라인 스타일을 확인했다.

- 실제 원인:
  - 두 겹이었다. ① 모달 라이브러리가 배경 스크롤을 잠글 때 스크롤바가 사라진 만큼을 `padding-right`로 보정해 주는데, 우리는 이미 전역에서 스크롤바 자리를 항상 예약해 두고 있었다. 보정이 중복돼 그 폭만큼 밀렸다. ② 애초에 알림함은 모달이 아닌데 모달로 열려 배경 스크롤을 잠그고 있었다 — 필요 없는 잠금이었다.

- 해결 방법:
  - 알림함을 비모달 드롭다운으로 전환해 문서 스크롤 잠금 자체를 없앴다. 보조 메뉴가 배경을 잠글 이유가 없다.
  - 스크롤바 자리를 예약하는 환경에서는 모달 라이브러리의 오른쪽 여백 보정이 적용되지 않게 했다. 실제로 스크롤바가 폭을 차지하는 환경에서는 기존 보정이 그대로 살아 있어야 해서, 환경 무관하게 끄지는 않았다.
  - "알림함은 배경을 잠그지 않는다 / 경매 미리보기는 계속 잠근다"를 회귀 테스트로 박았다.

- 다음에 비슷한 문제가 생기면 먼저 확인할 것:
  - 흔들림 폭이 스크롤바 폭과 같은지부터 잰다. 같으면 CSS 레이아웃이 아니라 스크롤 잠금 계열이다.
  - 오버레이를 열기 전에 "이 오버레이는 모달인가" 부터 정한다. 배경과의 상호작용을 막아야 하는가로 갈리고, 아니면 잠금 관련 부작용을 통째로 안 겪는다.
  - 라이브러리가 body에 넣는 인라인 스타일과 우리 전역 CSS가 같은 속성을 건드리는지 본다.
