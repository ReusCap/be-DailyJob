## be-DailyJob — PR

### 1. 오늘 완료한 것

- 오늘 실제로 끝낸 기능/수정/학습:
  - 데모를 대비해 홈 화면을 차량 판매 4단계가 잘 드러나도록 개편했다.
  - 판매·시세 조회 화면의 이미지, 문구, 여백을 정리하고 주요 사용자 흐름을 전반적으로 QA했다.
  - 방문 견적 완료 후 홈 이동 버튼을 추가하고 테스트용 차량 데이터도 보강했다.
- 아직 끝내지 못한 부분:
  - 거래 내역으로 바로 이동하는 진입점은 이번 작업에 포함하지 못했다.

### 2. 오늘 가장 의미있었던 기술적 판단

- 내가 내린 판단:
  - 홈 화면에서는 실시간 데이터를 조회하지 않고 고정된 예시 화면으로 판매 과정을 안내했다.
- 그렇게 판단한 이유:
  - 데모에서 데이터 상태와 관계없이 서비스 흐름을 안정적으로 보여주기 위해서다.
- 고려했지만 선택하지 않은 대안:
  - 홈 화면에서 실제 경매 데이터를 구독하는 방식은 복잡도와 데모 실패 가능성이 있어 제외했다.
- 코드 품질/테스트/유지보수에 미친 영향:
  - 데이터 의존성이 줄어 화면이 안정됐지만, 예시 값이 실제 데이터로 오인되지 않도록 관리가 필요하다.

### 3. 가장 막혔던 문제와 해결 과정

- 문제 상황 또는 증상:
  - 판매·시세 화면에서 핵심 입력 영역이 한 화면에 들어오지 않아 데모 흐름이 끊겼다.
- 처음 추측한 원인:
  - 히어로 영역과 설명 문구가 과도한 공간을 차지한다고 판단했다.
- 원인을 확인하기 위해 시도한 방법:
  - 화면별 높이, 여백, 폼 폭과 푸터 노출 여부를 직접 비교하며 QA했다.
- 실제 원인:
  - 콘텐츠 높이와 정보 위계가 정리되지 않아 핵심 행동이 화면 아래로 밀리고 있었다.
- 해결 방법:
  - 불필요한 설명을 제거하고 뷰포트 기준 높이를 적용했으며, 해당 화면의 푸터를 숨겼다.
- 다음에 비슷한 문제가 생기면 먼저 확인할 것:
  - 주요 해상도에서 핵심 CTA와 입력 영역이 첫 화면에 노출되는지 먼저 확인한다.

### 4. 오늘 잘한 행동

- 어떤 행동이었는지:
  - 개별 기능만 보지 않고 실제 데모 사용자 흐름을 따라가며 여러 화면을 함께 QA했다.
- 그 접근이 도움이 된 이유:
  - 화면 사이의 문구, 여백, 이동 흐름이 어긋나는 문제를 한 번에 발견할 수 있었다.
- 다음에도 반복하고 싶은 점:
  - 배포나 데모 전에는 대표 사용자 시나리오를 처음부터 끝까지 직접 수행한다.

### 5. 오늘 아쉬웠던 행동

- 비효율적이었던 접근/놓치거나 부족했던 점:
  - 기능 구현 이후에야 낮은 화면 높이와 데이터 상태에 따른 화면 변화를 집중적으로 확인했다.
- 그렇게 된 원인:
  - 초기 구현 단계에서 데모 환경과 해상도 조건을 충분히 정의하지 않았다.
- 다음에는 다르게 해볼 구체적인 행동:
  - 작업 시작 전에 데모 해상도와 테스트 데이터를 고정하고, 구현 중간부터 전체 흐름을 반복 점검한다.
